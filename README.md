# 交易日记助手

一个以对话采访为核心的交易复盘与日记助手。帮助你回顾操作、梳理不同时间周期的交易想法，持续维护持仓管理与计划买入记录，并在确认后保存到 Obsidian。数据用于辅助核对，不代替你的叙述和决策。

## 两类记录

- `持仓管理`：记录仍在管理中的标的、交易工具和具体想法。
- `计划买入`：记录计划买入或继续观察的标的、交易工具和具体想法。

按标的记录实际交易工具和具体想法；触发、退出、加仓或减仓条件如果存在，就写进具体想法，不额外制造必填字段。未实施的想法可以继续有效，已经买入也不代表持仓管理结束。保留“考虑”“可能”等不确定性，期权术语使用英文 `Call` / `Put` / `Long Call`。

## 日常使用

每天先读 `25 投资交易` 中的当前计划记录、相关旧日记和当天旧记录，再采访用户本次操作、等待原因或计划变化的叙述。若只有旧不可变计划版本而没有普通计划落点，先向用户确认目标和承接范围，不静默迁移。已有回答不重复问，只追必要缺口；没有当日叙述时不自行补写。暂缺数据时仍可如实记录用户想法，但要明确区分自述、数据事实和分析推断，不能把自述标为独立核验的成交、持仓或行情事实。

先展示具体 Markdown 草稿。对未来动作保留“考虑”“可能”等原语气，不自动升级为确定执行；新建或修订仅在展示具体内容并得到用户确认写入后保存，不强制新版本或固定问卷。确认后的每日内容写入现有 `25 投资交易/10 每日复盘`，周度回顾写入 `25 投资交易/20 周度复盘`，当前计划沿用 `25 投资交易/30 已确认计划摘要` 内的现有落点；若那里尚未有已确认的普通计划落点，先向用户确认目标和承接范围，不另建源。无变化时为 `no_op`。写入前重读并发；已有 managed 日记只在既有 managed 边界内更新，没有 managed 的普通计划笔记只改用户确认的段落，保留其余手写内容，不强制新建 managed 区域或 schema。写后先文件系统回读，再顺序做 Obsidian CLI 回读。

## 技术面与周末

只有在用户讨论已筛选标的且请求参考时，才提供轻量 PA 支撑、压力或条件判断。以 Al Brooks Price Action 为主，日线作为背景、小时作为执行；按用户请求读取对应周期数据复验，并注明来源、截至时间、周期和 K 线已完成或形成中。数据、周期或时间不足就报告缺口，不以日线替代小时验证，不把目标价当已证实压力位，也不把触价当成交。

默认基线使用 Longbridge CLI 做行情、持仓和成交的只读核对；其他券商只在实际需要时映射相同字段含义，不预建通用适配层。现有 helper 可选且保持不变，不是 Longbridge CLI 封装或多券商接入层。只读核对能力与本批真实验证分别报告，不自动调用其他研究 Skill，不重新选股或做基本面，也不把量化研究变成实盘方法。

周末只回顾本周已发生的操作和计划实施，区分已实施、仍等待和缺少证据。仍有效的计划跨周沿用；只有用户确认作废后，才把具体对象单独展示并归档到现有私有知识库，不直接删除或自动失效。周度说明写入 `25 投资交易/20 周度复盘`。Skill 支持生成周末回顾；本轮不配置或声称同步定时任务，调度配置需另获授权。

## 边界与验证

沿用现有隐私边界：只读取本次核对所需的持仓、成交和行情字段，不下单或修改订单；余额、购买力、盈亏、原始券商响应、凭据、账户或请求标识，以及完整期权合约身份不写入仓库、普通日志或公开日记。不恢复 Web UI、SQLite 或 Bridge。现有只读成交/合约辅助脚本可按需参考，但不是每日主流程；本轮不强制机器投影、不可变版本或 schema，也不迁移真实记录。

# daily-trade-journal v2 架构报告

> 当前规则补充：2026-09-05 用户已确认实施第 10 节的证据优先修订。第 1、8 节的 Vault 迁移和批准范围仅记录 2026-09-04 历史批次，不授权本次写 Vault。当前操作细节以两个 Skill 及其引用契约为准；本报告记录决策与验证边界。

## 1. 目标与批准范围

本报告记录 2026-09-04 经用户确认的 Obsidian 交易记录重构。目标是把三种不同时间语义分开：

- `当前交易计划` 回答现在准备怎么做，并随确认后的每日 PA 持续更新；
- `计划历史快照` 回答某笔交易发生前当时准备怎么做，快照创建后不改；
- `每日复盘` 回答某一交易日实际发生了什么、与事前计划如何对应，以及收盘后计划为何变化。

“历史快照不改”不代表计划不变。当前计划必须根据新的已完成日线、量价、EMA10/20、Cycle 阶段和关键位置更新；盘中操作依据是已完成 1H K 线。行情变化先形成草稿，只有用户确认后才更新当前计划并留下新的历史快照。

本批允许修改 Obsidian 目录、索引、模板、当前计划、创建当日复盘和新历史快照，并同步修改两个 Skill、README 与本报告。历史计划文件内容保持不变；不修改 `开发路径图.md`，不访问或修改订单，不恢复 Bridge/SQLite/UI，不更新自动化，不 push 远端。

## 3. 真源与时间语义

### 3.1 当前状态

`当前交易计划.md` 是人读的当前状态入口。它可以更新，但只能由一个已经写入并双重回读成功的历史快照生成。机器对成交做历史核对时不能只读当前计划。

### 3.2 事前状态

历史核对使用确认时间和生效交易日不晚于相关交易的最近快照。新快照只能追加，不能覆盖旧文件。同一天允许多次确认和多个快照；如果计划没有变化，不为了凑日期生成新快照。

现有 `daily-trade-journal-confirmed-plan.v1` 机器区块继续保留。本次只重构人读结构和路径，不同时发明 v2 schema。未来若需要修改机器字段，必须单独设计迁移和回归范围。

### 3.3 当日事实

每日复盘按被复盘的美股交易日命名。一份每日复盘可以引用：

- `plan_before`：交易发生前适用的历史快照；
- `plan_after`：复盘后确认的新快照，或 `unchanged`。

这样可避免用事后更新的当前计划倒推昨日操作。用户确认某操作来自未持久化的盘中计划时，记录“用户确认计划内；历史计划记录缺口”，不能因缺口自动判为偏离，也不能伪造事前文件证据。

## 4. 日常流程

### 4.1 日期、恢复与客观核对优先

提问前读取上一份每日复盘、当前交易计划、适用历史快照和与同一日期/任务匹配的脱敏恢复候选。Obsidian 已确认内容优先；临时草稿只能恢复讨论上下文，不能补造计划、成交或 PA 事实。

先分别明确北京时间运行日、最近已完成美股复盘日和当晚计划日，然后读取脱敏成交及具体标的的已完成日线/1H，逐笔选择当时适用的最近确认计划并展示客观核对。采访只收集尚缺的理由、宏观判断或临时调整，不阻塞独立数据读取，也不重复询问已知动作和顺序。复盘不是交易习惯纠正表，不要求填写“做对了什么/需要修正什么”。

### 4.2 事实、计划与盘面对齐

逐条交易分开记录：

1. 用户叙述；
2. 事前历史快照；
3. 对应窗口的已完成盘面事实；
4. 支持、冲突、证据缺口和计划对齐。

用户叙述不是 broker fact，PA 推断不是成交事实，当前计划不是事前证据。缺失、不适用和冲突分别保留，不能用流畅文字补齐。

### 4.3 PA 与当前计划更新

当前计划按已筛选标的更新，不做市场扫描。默认只做单边上涨：

- 日线判断 Cycle、市场状态、关键位置、量价、EMA10 和 EMA20；
- 已完成 1H K 线是盘中操作依据；
- 盘前价格和形成中 K 线只更新观察状态；
- 到达缺口、EMA 或突破位不是买点；
- 每个买入候选依次写位置门槛、1H 做多信号 K、跟随/二次进场、失效后等待；
- Cycle 用底部反转/wedge pop、突破后整理/二次进场、extension/buy climax 三阶段组织；
- 下跌分支只产生不买、等待、减仓或退出，除非用户另行确认独立做空计划。

### 4.4 宏观研讨

宏观由用户的主题、判断、消息或问题驱动。保留用户原始主张，再核验事件、数据时间、市场反应、支持证据、反例、因果跳跃和替代解释。宏观结论只能作为背景；若它改变标的、动作、工具或条件，必须进入计划变化草稿并由用户确认。

长期笔记不保存精确数量、成交价、成本、费用、盈亏、完整期权身份、账户/订单/成交标识或原始 provider payload。

### 5.2 当前交易计划

固定顺序：当前版本和数据状态、全局 PA 规则、当前持仓管理、计划买入、继续观察、暂停或缺少计划、待确认事项、最近历史快照。每个标的使用具体工具类别；工具未知时明确写待确认，不用“其他期权”替代 Call/Put。

### 5.3 计划历史快照

固定顺序：相对上一快照的变化、全局规则、全部持仓管理、计划买入、继续观察、暂停/缺少计划、待确认事项、机器区块。快照 frontmatter 记录 `plan_version`、`source_review_date`、`effective_trading_date`、`confirmed_at`、`supersedes` 和确认状态。

## 6. 写入事务与失败处理

收到明确确认后：

1. 重读目标每日复盘、当前计划和当前快照指针，记录内容哈希或等价并发证据；
2. 有计划变化时先创建新历史快照，使用不覆盖写入；
3. 文件系统和 Obsidian CLI 都能读回新快照后，写每日复盘并链接 `plan_before` / `plan_after`；
4. 每日复盘双重回读成功后，最后更新当前交易计划；
5. 当前计划双重回读成功后才标记 current；
6. 任一步失败就停止后续步骤并保留 partial/blocked，不自动重试未知外部副作用；
7. 无计划变化时只写每日复盘，不生成快照。

该顺序允许中断时留下一个尚未成为当前指针的孤立新快照，但不会让当前计划指向缺失或未验证内容。恢复时应先核对它与确认内容，再决定继续或标记未采用。

## 7. 状态、隐私与权限

计划来源、broker fact、daily note、journal、macro、PA 和写入回读分别维护状态。测试通过、文件存在、CLI 返回成功或当前计划更新，都不能证明 broker 数据、PA 结论或人类验收 PASS。

任何长期笔记、Git、普通日志和 private temp 都不得包含原始券商响应、账户/订单/成交标识、精确数量、成交价、成本、费用、余额、盈亏、凭据或完整期权合约。工具只读核对不修改订单或账户。

## 8. 迁移与回滚

本次迁移将可见目录改为 `30 交易计划/当前交易计划.md` 与 `历史快照/`，并更新 Vault 和仓库中的引用。三个既有历史文件只移动路径，不修改内容。新当前计划由新确认快照生成；旧索引不作为第二真源保留。

仓库改动以一个本地 checkpoint commit 为回滚边界；Vault 迁移前保存精确路径、内容哈希和临时备份。若写入失败，不自动删除或覆盖已写入文件，报告具体 partial 状态。远端 push、自动化重跑、路线图修改和人类验收均不在本批范围。

## 9. 对抗性复核结论

- 若只维护一个可变计划，事后无法证明交易前的真实计划，因此保留历史快照。
- 若把完整当前计划复制进每日日记，会形成多个竞争真源，因此每日复盘只保存当日事实、持仓角色和计划变化。
- 若当前页与历史快照分别手工维护，会发生漂移，因此当前计划必须从最新已验证快照生成。
- 若每个交易日强制生成版本，会制造无意义重复，因此只有确认后的计划变化才生成快照。
- 若同时修改机器 schema，迁移风险会盖过本次信息架构目标，因此暂留 v1 兼容区块。

上述反例已纳入设计。真实 Obsidian 写入、Skill 校验、本地 Git commit 和用户对可读性的验收仍是分开的证据通道。

## 10. 2026-09-05 证据优先修订（实施已批准，真实运行待验收）

### 10.1 决策、范围与替代方案

用户要求核对具体标的走势，并确认修改已审查的六项：先客观核对再采访、逐笔计划与行情时间匹配、待核验与最终结论分离、内存脱敏、模块级失败隔离、北京时间晨间日期规则。本批只改两个 Skill、引用/展示文案、离线脱敏入口及其回归测试、README、本报告与现有 automation-2 提示词。日程为北京时间周一至周五 09:00；保留模型、项目及其他自动化设置。不得下单、写 Vault、改历史快照、宏观假说、setup catalog 或开发路径图；不 push 或合并 main。

不采用“采访后才能读行情”：主观解释不是可观察事实的依赖。不采用“展示时才遮挡原始输出”：进入工具上下文或日志后已发生泄漏。不扩展旧计划 schema/投影器为新行情引擎：当前缺陷主要在编排及采集输出边界，保留旧兼容接口，明确它只做字段初配。使用标准库与现有解析器，新增 stdin-only 原子脱敏入口，不另建券商连接器或自动交易服务。

### 10.2 合同与失败边界

- 复盘时间：逐笔采用确认/生效均适用的最近计划；同日修订按各笔时点选择。触发证据必须在成交时已经完成且可获得。事后收盘、后来跟随、修订后的历史数据不能无说明反证早盘已触发。
- 计划时间：晨间最新完成日线/1H 服务当晚条件草稿；未来信号仍等待。交易日历必须核验，周一回看上周五，假期、半日市和夏令时按实际会话处理。当晚休市不自动改生效日；重复复盘只处理增量。
- 采集边界：调用方先核实 provider 日志与进程捕获安全，再在内存处理成功响应；脱敏器本身不调用 provider，不读取日志，不证明实际采集安全。输出仅允许字段，失败返回固定错误且整批不泄漏；同源批次失败不能绕过原子校验挑行输出。
- 时间投影：原始成交时点只用于内存排序及与公开 cutoff 的 before/equal/after 比较；同刻同 sequence，不虚构顺序。cutoff 的来源、完成性和 available_at 由分析流程核验，关系输出不是 PA 结论。
- 工具映射：无可信 instrument 时非期权类别未知，不猜测 ETF；数字根代码暂拒绝。重新支持需有真实格式文档、隐私反例及合成回归证据。

| 情况 | 应有行为 | 不允许的升级 |
| --- | --- | --- |
| 尚未取行情 | PENDING，继续取相关标的证据 | 全部写“无法核对” |
| 客观证据足够，动机未答 | 给客观结论，动机待补 | 采访阻断核对 |
| 一个标的缺 1H | 该条件 partial，其他项继续 | 全局停止或虚构信号 |
| 有计划但定义“站稳”不清 | 展示已查走势及定义缺口 | 事后自定阈值 |
| 无成交 | 继续持仓、当晚计划、未决事项 | 直接 no_op |
| 券商源隐私/解析失败 | 停该源；独立公开行情可继续 | 回显响应、异常或日志 |
| 写入回读失败 | 停相关写入链并对账 | 标记 written/current |

### 10.3 检查、对抗复核与剩余验收

以 stdin/stdout 合成回归检查允许字段、Call/Put 与 0DTE、未知合约、整批失败无回显、排序及同刻、公开 cutoff、跨交易日、空数组与失败响应、持仓工具映射和输入大小限制。运行既有投影器测试防止导入依赖回归；Skill 格式与 diff 检查独立记录。

编排反例复核六种场景：已有计划且未采访仍应查走势；同日改计划逐笔取版本；早盘成交不得借日终 K 线；单项缺 1H 不阻塞其他标的；无成交但有持仓仍分析；周一/假期/半日市/夏令时不机械减一天。它们是指令级审查，不冒称新的自动日历或 PA 引擎测试。

审查处理：采访前置与全局停止（accepted → fixed，改编排和提示词）；收盘后持仓标题误导（accepted → fixed，改为当前并要求采集时点）；未知非期权被猜为正股（accepted → fixed，无 instrument 输出未知）；旧 schema 迁移（deferred，本批不需要且迁移风险独立）；真实 provider 日志安全及数据权限、完整自动化运行（deferred，本批不读券商，待实际运行核验）。用户确认实施不等于人类验收，验收仍 PENDING。

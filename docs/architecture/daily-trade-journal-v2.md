# daily-trade-journal v2 架构报告

## 已批准定位与取舍

2026-09-03 已批准将 `daily-trade-journal` 定位为“交易日记助手”：以对话采访和用户叙述为核心，用普通 Obsidian Markdown 维护 `持仓管理` 与 `计划买入` 两类记录。这样能保留用户对操作、触发、加减仓、退出和等待原因的原意，数据只用于辅助核对，不代替叙述或决策。

每个标的记录实际交易工具和具体想法；未来动作保留“考虑”“可能”等不确定性，期权术语使用英文 `Call` / `Put` / `Long Call`。不强制固定问卷、评分、机器匹配、后台字段或结果评价，也不对未完成交易过早下结论。预建通用券商适配层、强制 schema/机器匹配和另建 Skill 均排除，以保持本次改动小且可复核。

## 工作流与数据边界

日常先读取 `25 投资交易` 中的当前计划、相关旧日记和当天旧记录，再采访用户本次操作、等待原因或计划变化；已有回答不重复问，只追必要缺口。没有用户当日叙述就不自行编写日记。先展示具体草稿，用户明确“确认写入”后保存；无变化返回 `no_op`。

技术讨论只在用户已筛选标的且请求参考时进行，以 Al Brooks Price Action 为主，区分日线背景与小时执行。按用户请求读取对应周期数据复验，注明来源、截至时间、周期及 K 线已完成或形成中；数据、周期或时间不足就报告缺口，不以日线替代小时验证，不把目标价当已证实压力位，也不把触价当成交。分别标明用户自述、数据事实和分析推断，不自动调用其他研究 Skill、不重新选股或做基本面，也不把量化研究变成实盘方法。

沿用已确定的单一基线券商，未另行指定时默认 Longbridge CLI；由 Agent 按需做行情、持仓和成交的只读核对，不把不同券商持仓/成交混合成同一账户记录。其他券商只有在实际需要时映射相同字段含义，不预建通用适配层。仓库现有 helper 可选且保持不变，它们处理已有输入，不是 Longbridge CLI 封装或多券商接入层；普通日记不以这些工具或数据为前置条件。只读能力与本批真实验证分别报告。

确认后的每日内容写入 `25 投资交易/10 每日复盘`，周度回顾写入 `25 投资交易/20 周度复盘`，当前计划沿用 `25 投资交易/30 已确认计划摘要` 的现有落点；没有普通计划落点时先确认目标和承接范围。旧 immutable 版本只作只读历史参考，不原地覆盖或迁移；仍有效的计划跨周沿用，只有先展示具体对象，经用户单独确认作废并单独确认归档才归档，不自动删除、失效或同步。写入前保留可恢复备份，重读 live 文件并检查并发；已有 managed 日记只改既有 managed 边界，没有 managed 的普通计划笔记只改用户确认的段落并保留其他手写内容；写后按文件系统再 Obsidian CLI 顺序回读，失败停止后续写入并报告未验证。

只读取本次核对所需的持仓、成交和行情字段，不下单或修改订单；不扩展到余额、购买力、盈亏或其他不必要的账户信息。账户或请求标识、原始券商响应、凭据、敏感记录和完整期权合约身份不进入仓库、普通日志或公开日记。具体期权身份如已有明确授权的私有预览需要，仍限于该边界。

## 失败矩阵

| 阶段 | 失败或未知 | 处理与回滚边界 |
| --- | --- | --- |
| 读取与核对 | 数据、来源、周期或时间缺失，或事实无法核验 | 保留自述与缺口的区别，标记 `blocked`/`NOT RUN`，不把缺失写成无成交、无持仓或已验证 PA 结论 |
| 草稿与确认 | 用户尚未确认，或确认范围不清 | 只展示草稿，不写入；必要时重新确认目标和承接范围 |
| 写入前 | live 文件发生并发变化 | 保留原文并停止，不覆盖新修改 |
| 写入后 | 隐私检查、文件系统回读或 Obsidian CLI 回读失败 | 停止后续写入，报告写入未验证，不自动回滚；需回滚时先重读，发现新修改不得覆盖 |
| 归档 | 用户未单独确认作废 | 不归档、不删除、不自动失效 |

## 迁移、维护与回退

本轮不迁移真实计划或日记，不配置调度，不声称自动化、真实行情或真实 Obsidian 写入已运行。现有 helper 的输入、隐私和维护边界保持不变；本轮维护责任只覆盖 Skill 入口、界面提示、README、架构说明，以及 `开发路径图.md` 顶部仅三处批准替换。后续仅允许按批准文本更新 GitHub About description，其他仓库 metadata 不改；该授权不代表已执行。

本批 Git 回退参考基线为 `0bc7142658d7a50a56206eeb0a2a9dfa8817d287`；五个批准文件和路径图三处替换构成本批边界。集成后如需回退，先复核并确认本批反向 diff，以新提交撤销，不改写 `main` 历史，不影响真实记录、调度或其他修改。

## 证据与状态

Skill、界面提示和文档属于本轮修改范围；本地测试、Skill validator、配置读回和 `git diff --check` 只证明各自的本地约束。真实 Longbridge 只读核对、真实 Obsidian 写入、真实计划迁移、调度或同步均为 `NOT RUN`；人类功能验收为 `PENDING`。任何 `blocked`、`PENDING`、`NOT RUN` 或 `no_op` 均保持原状态，不由较低层证据升级。

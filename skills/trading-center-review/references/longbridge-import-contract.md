# Longbridge 周度导入契约

## 前提

开始前必须确认当前工作流的授权范围。当前用户政策允许 Longbridge `positions --format json` 作为例行的最小只读持仓同步；不允许由该例外外推到 Longbridge 成交、订单、资金、利润、对账单或凭据。周六周度报告如要给出整周账户净值、整周交易和盈亏，必须由用户在本线程另行明确授权 Longbridge、读取、具体整周窗口和 Git 工作树外的私有输出路径；该授权只覆盖列明的接口和日期范围。不要下单、改撤单、读取/输出凭据或请求无关实时行情。若没有对应范围授权，将所有成交、结果和账户覆盖范围标为“未验证”。

## CLI 契约参考（必须在当前环境重验证）

如果当前环境已安装兼容版本的 `longbridge` CLI，可按下列只读命令契约进行能力检查；版本、登录状态、字段和参数必须在本次运行前重新验证，不得把本文件当作当前环境可用性的证明。

| 命令 | 用途 | 使用字段/限制 |
| --- | --- | --- |
| `positions --format json` | 例行只读持仓同步 | 私有运行目录可保留标的、数量、可用数量、成本和币种等复盘所需字段；不得写入 Git/Wiki；仍只是读取时快照 |
| `order --history --start --end --format json` | 历史订单聚合 | 仅默认按方向/状态计数，不写订单 ID 或价格 |
| `order executions --history --start --end --format json` | 历史成交聚合 | 仅默认输出成交条数，不写成交 ID、标的、数量或价格 |
| `assets --format json` | 获授权的账户资产当前快照 | 仅可在周度账户结果授权后调用；不得把当前快照冒充周初/周末历史值 |
| `profit-analysis --start --end --format json` | 获授权的整周账户净值与盈亏聚合 | 仅使用明确的整周窗口；保留 initial/ending asset、sum profit、yield 和接口缺口，不输出原始响应 |
| `profit-analysis by-market --start --end --format json` | 获授权的标的/市场级盈亏数量对比 | 仅在明确授权后调用；接口未提供已实现/未实现拆分时不自行拆分 |
| `cash-flow --start --end --format json` | 外部资金流、分红、结算勾稽 | 仅当授权明确包含资金流核对时调用；不因净值变化而自动扩展读取范围 |
| `kline history <SYMBOL> --period day --start --end --format json` | 已完成日线市场事实 | 只对实际成交/持仓标的请求；期权先映射到标的股票，保留期权成交本身 |

`longbridge check --format json` 只用于连接/令牌健康检查。它的通过不证明账户完整性、跨账户对账、历史持仓覆盖或字段许可。

CLI 运行可能产生日志；所有实际调用应以 Git 工作树外的私有输出目录作为工作目录，并在运行后检查项目工作树没有新增券商日志或原始数据。

## 最小检查

1. 记录本次 Longbridge 持仓同步范围、读取时间和计划的私有输出位置。
2. 对本地导出检查文件格式、可识别列名、日期范围、币种与缺失字段；对 CLI 先执行 `--schema` 或 `check`，再调用已授权的最小读命令。持仓同步只调用 `positions --format json`，不调用 Longbridge 其他账户接口。美股订单/成交按 `America/New_York` 日历日的半开区间读取，并记录转换后的 RFC 3339 UTC 窗口；不得以 UTC 或机器本地零点代替美东日界。不得假定 CSV/JSON 的固定 schema。
3. 任一历史订单/成交查询发生 CLI、解析或返回结构错误时，标记“未验证/查询失败”，保留错误分类；只有成功解析出的空数组才可表述为“接口在该窗口返回 0 条”，且不得推断账户没有交易。
4. 检查输出位置不在项目 Git 工作树内。原始导出不得复制、暂存或提交到 Git。
5. 只提取为本周复盘必要的聚合事实。账户标识、订单编号、精确持仓、成本、价格、成交 ID 和原始行保留在私有环境；如需引用，先取得字段级许可。
6. 周度账户结果必须同时读取本周与上周同口径窗口（若授权包含上周比较），使用接口明确返回的周初/周末资产值和盈亏字段；没有历史每日资产轨迹时，不用当前 `assets` 快照补齐。
7. 将“文件可读”与“数据完整、账户完整、已对账”分开。缺失一个账户、时段、币种或产品范围时，标 `partial_data` 或 `未验证`；未读取 cash-flow 时，净值变化与交易盈亏的勾稽保留缺口。

## 草稿最小字段

- 授权状态与数据状态
- 覆盖时间、来源类型、可见范围和缺失项
- 已确认事实（只放已获授权的最小聚合）
- 计划 vs. 实际、过程复盘、可复用规则
- 下周观察池、风险、待确认项

## 禁止事项

不要输出交易指令，不要把导出数据写入项目或 Wiki，不要因部分数据而推断总账户、盈亏或执行质量。没有对应授权时不得调用 `assets`、`profit-analysis`、`profit-analysis by-market` 或 `cash-flow`；任何需要新增读取或写入范围的步骤都暂停并向用户请求确认。

# 复盘看板可视化契约

## 目的

将每日盘前与周度复盘稳定渲染为直接可打开的 standalone HTML，同时把账户证据、交易计划和相关事件视图分开。每日 HTML 是用户可见主交付；完整 Markdown 和全量事件日历只作为私有审计工件。HTML 不是券商记录、交易指令或公开报告。每日与周度的信息架构不同：每日聚焦账户证据、当前持仓/Plan 交易计划和相关事件；周度才按周度契约承载组合逻辑、整周损益与执行复盘。

## 固定信息架构

每日输出顺序不得改变：

1. `账户与交易证据`：先展示授权、时间窗口、订单/成交与快照边界；默认不采集、不展示资金流水。
2. `交易计划`：使用两个 CSS 标签页 `当前持仓` 与 `Plan`。`当前持仓` 只表示读取时快照，不因持仓当前走势倒推策略；`Plan` 只表示尚未持仓但已进入有效计划的标的。卡片标题不重复添加标签页名称，且一张卡只对应一个明确 ticker。
3. `持仓与计划相关重要事件`：底层可读取 Longbridge Calendar/News 或其他获准的全市场数据，但可见层只保留与当前持仓、期权 underlying、本周有效计划或明确候选直接相关的美股财报，以及对这些对象有明确风险通道的美国宏观、政策、监管和行业事件；事件不混入计划卡。

周度输出可在周度契约允许的范围内增加 `交易风格与整体逻辑`、`本周损益与执行复盘`、周初/周末净值与整周账户结果等区块；不得把周度区块反向塞入每日看板。

交易计划语义固定为：`趋势交易`、`震荡区间`、`反弹`、`突破`、`抄底`。它们描述已确认的计划行为，不描述当前持仓走势；“震荡区间”专指区间上下沿交易。未明确策略的持仓保留“策略未单列”，临时加仓不另设分类；买入时才确认策略的标的保留“策略待买入时确认”。

## 每日事件筛选门

- 先把完整机械日历保存在私有运行目录，再派生可见相关事件视图；不得直接把全量日历塞入看板。
- 财报事件必须能唯一映射到美股 ticker，并命中“当前持仓 underlying ∪ 本周有效计划 ∪ 明确候选池”。无关港股、外国公司、ADR 和其他美股财报不显示；若当前持仓或候选本身是 ADR，则仍可按相关性保留。
- 宏观、政策、监管和行业事件必须写具体名称、双时区、状态、来源和影响通道；“3 星宏观事件”“重要数据”等泛称不得进入看板。
- Fed 官员讲话、证词、访谈或讨论只有在官方日历确有日程时才显示；没有日程时不生成占位事件或影响卡。FOMC 会议、纪要和官员讲话必须分开标识。
- Longbridge News 的盘中/夜盘条目以本轮生成时刻为确定性截止：时间完整且已发生的条目从当前可见事件组剔除，但保留在私有完整工件和审计说明中；时间缺失或接口失败必须保留“未验证”边界，不能静默当作空事件。
- 相关事件筛选后为空时可省略该日事件组；接口失败则必须显示一条脱敏的 `未验证` 错误事件，不能省略或冒充成功空列表。
- 事件影响只映射可见事件，不重复全量事件，也不为被过滤的无关事件逐条写“无直接影响”。

## 渲染方式

使用：

```bash
python3 scripts/render_trade_review_dashboard.py \
  --input /私有运行目录/review-dashboard.json \
  --output /私有运行目录/trade-review-dashboard-standalone.html
```

输入与输出都必须位于 Git 工作树外。渲染器从 `assets/trade-review-dashboard-standalone.html` 读取固定样式，直接生成一个 HTML 文档；禁止改回 `document.write`、动态脚本注入、iframe `srcdoc` 或依赖外部 CDN 的实现。所有输入文本均按纯文本转义，不能在 JSON 中注入 HTML。

## 数据与发布边界

- 模板、渲染脚本、契约和无真实数据的测试可以进入 Git。
- 每期 JSON、渲染后的 HTML、账户净值、逐标的损益、持仓、成交与个人计划必须留在私有运行目录，不得提交或推送。
- 看板只能呈现已获授权的数据范围。模板存在不构成账户读取授权。
- 不把资金流水业务类型作为复盘完成门槛；只有用户明确要求资金勾稽时，才在 Markdown 私有证据中单独处理，默认看板不显示。
- 输出文件权限固定为仅所有者可读写。模板或 Schema 校验失败时返回 `blocked`，不得生成半成品并声称完成。

## 验收检查

1. 直接用浏览器打开生成文件，无网络请求、无控制台语法错误、无 iframe、无 `document.write`。
2. 桌面宽度和手机宽度均可读；表格可横向滚动，计划和事件可用原生 `details` 展开。
3. 每日看板先显示账户证据，再显示当前持仓 / Plan 两个交易计划标签页；周度看板若含损益与执行复盘，证据边界必须位于其上方。资金流水、部署信息和证据复核任务不出现在计划区。
4. 计划卡全部有 ticker；当前持仓未明确策略时显示“策略未单列”，不把持仓走势或临时加仓强行改写为五类策略。
5. 事件区仅含相关事件视图，逐条保留具体名称、来源、状态、双时区和影响通道；抽查确认没有无关港股/外国公司财报、泛称“3 星宏观事件”或“无 Fed 演讲”占位行。
6. 输入中的 `<script>`、引号和 HTML 标签在输出中均被转义为文本。

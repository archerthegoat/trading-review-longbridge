# 交易中心复盘

将交易事实、分析和行动项分开记录。每日复盘的用户可见交付默认是私有 standalone HTML 看板，中文 Markdown 只作为同一事实边界的私有审计草稿；周度复盘仍按周度契约交付完整正文。所有输出仅为决策支持，绝不下单、改撤单或把私有券商数据写入 Git。

## 先做状态与授权门禁

1. 读取当前项目的 `AGENTS.md`、`CONTEXT.md` 和现有交易中心材料；缺失时记录为“未验证”，不可用旧线程或猜测填补。
2. 将每个结论标记为：`已完成`、`待用户授权`、`未验证` 或 `阻塞`。将用户陈述、导入事实、分析判断分别标注。
3. 默认只读项目公开/可追踪材料。Longbridge 仅允许按 [Longbridge 导入契约](references/longbridge-import-contract.md) 例行只读同步当前持仓快照，不得因此读取成交、订单、资金、利润、对账单或凭据；本流程不提供其他券商接入。
4. Longbridge 持仓同步是最小只读范围；其他 Longbridge 私有接口或本地导出仍须在**本线程**清楚授权，且授权只覆盖指定范围。先读取 [授权与数据边界](references/authorization-and-data-boundary.md) 与 [Longbridge 导入契约](references/longbridge-import-contract.md)。
5. 任何飞书 Wiki 写入都须先展示目标空间/节点、待写内容和最小写入范围，并在本线程取得单独确认；未确认时只生成本地草稿。Longbridge 持仓快照不得因同步而自动写入 Wiki。

详见 [授权与数据边界](references/authorization-and-data-boundary.md)。

将飞书 Wiki 作为经确认后的记录主库时，先采用 [Wiki 文档数据结构](references/feishu-wiki-record-structure.md)。原始券商导出仍留在私有运行目录；Wiki 只写入获许可的事实或聚合。

## 工作流

### 日常主动录入

从 [日常录入模板](assets/daily-entry.md) 创建条目。接受用户提供的计划、观察、执行理由、情绪和复盘线索；不要求也不推断券商数据。把不确定信息写为“待补充”，并记录日期、市场时区和证据来源。

### 每日复盘

使用 [每日复盘模板](assets/daily-review.md)。先确认复盘阶段：开仓后记录或平仓后复盘；混合描述时先问：`这笔交易是刚下单/刚成交，需要做下单后记录，还是已经结束，需要做结束后复盘？`

将“计划 vs. 实际”“可复用规则”“明日需确认事项”分开。没有获授权的成交或账户事实时，写 `未验证：需要用户提供或本线程授权的导出数据`，不要杜撰结果、点位、盈亏或仓位。

#### 交易行为标签与持仓记录语义

- `趋势交易`、`震荡区间`、`反弹`、`突破`、`抄底`只描述已经确认的交易计划行为，不描述现有持仓当前正在经历的走势；其中“震荡区间”专指围绕区间上下沿的交易，不等同于泛泛的震荡持有。
- 当前持仓页是读取时快照与持仓记录，不强行给每个持仓贴策略标签。用户未明确该笔交易策略时保留“策略未单列”；既有持仓的临时加仓不自动创建新的策略类别，只有在计划或买入时确认的行为才进入五类分类。
- 用户明确新开仓策略时记录该计划语义；若经纪商订单/成交窗口未覆盖，仍须把用户确认、快照支持和执行未验证分开写，不能把策略标签当作成交事实。计划在买入时才确认的标的保留“策略待买入时确认”。

每日复盘的“当天交易日重要事件”和“下一美股交易日重要事件”必须使用同一张五列表格，不得退化为无来源的逐行清单：`Asia/Shanghai 时间 | 美东时间 | 事件 | 状态 | 来源与数据状态`。日期和时区写在表格标题前；美东时间必须保留，即使来源只给出 Asia/Shanghai 时间。状态统一使用“已发生 / 预期 / 未公布 / 未验证”，并按以下机械规则判定：事件的 `公告` 字段有非空有效值时必须标记“已发生”；公告值为空且事件时点尚未到时标记“预期”；事件时点已过但来源仍没有公告值时标记“未公布”；日期、时间或接口字段不完整/查询失败时标记“未验证”。没有事件也保留表头并写一行“无已确认事件”。来源列至少写确定性数据源或明确的 `机械读取/未验证`，不得省略数据状态。

事件信息的采集和交付必须走同一条可核验链路：当天日期和下一美股交易日分别生成私有事件工件；运行 `scripts/align_market_watchlist.py` 时，`--symbols` 使用默认观察池与当前周计划、当前持仓标的（期权先映射 underlying）的去重并集，不得只使用默认观察池。Longbridge 财经日历的 `data.list` 与直接 `list` 响应都必须解析，完整机械返回只保留在私有事件工件中。每日看板和私有 Markdown 草稿使用同一份**相关事件视图**，不得把完整日历复制到用户可见层：

- 财报只保留能唯一映射为美股 ticker，且 ticker 属于当前持仓（期权先映射 underlying）、本周有效计划或明确候选池的事件。与这些对象无关的港股、外国公司、ADR 或其他美股财报只留在私有原始工件；相关 underlying 本身是 ADR 时不得仅因 ADR 身份删除。
- 宏观、政策、监管和行业事件只保留对美股整体或上述持仓/计划有明确风险通道的高相关事件；必须写出具体事件名、时间、状态和来源，不能用“3 星宏观事件”等泛称代替。Longbridge 星级筛选为空但官方来源存在相关事件时，分开写明两种来源状态。
- Fed 筛查只在官方日历确有已排期的讲话、证词、访谈、讨论、FOMC 会议/纪要等相关事件时生成事件行；没有相关日程时不生成“无 Fed 演讲”占位行，也不把日常统计发布伪装成 Fed 官员讲话。历史核对必须区分“FOMC 纪要”和“官员演讲”。
- Longbridge News 的盘中/夜盘条目以本轮事件工件生成时刻为确定性截止：时间完整且已在生成时刻前发生的条目从当前可见事件组剔除，但仍保留在私有完整工件与审计说明中；时间缺失或接口失败不得静默删除，须按“未验证”保留错误边界。
- 相关事件视图成功为空时，私有 Markdown 五列表保留一行“无已确认事件（相关筛选后）”以满足审计结构；看板可直接省略空事件组。接口失败时保留具体错误和“未验证”，不得写成成功空列表。

两张事件表之后必须增加 `事件对当前持仓/计划的主要影响`，分别覆盖当天和下一美股交易日；影响摘要只映射相关事件视图中的事件，不重复完整日历，也不为已被过滤的无关事件生成“无直接影响”行。可按同一风险通道合并，但要列出事件名称。摘要列为 `事件 | 影响对象/风险通道 | 主要影响 | 证据与边界`，明确区分公告事实、研究判断和仍待验证的缺口，不生成买卖指令，也不把预期写成结果。每日私有 Markdown 草稿必须通过 `scripts/validate_review_draft.py` 的事件表头、章节、实际公告状态和影响摘要检查；事件章节或影响摘要缺失即视为复盘阻塞。每日最终对话只交付通过渲染和检查的私有 HTML 看板链接，以及必要的阻塞/缺口短说明，不再粘贴完整 Markdown 正文或两张事件表。

当用户额外要求未来两周或更长窗口的持仓相关行业/公司事件时，未来窗口必须与“下一美股交易日重要事件”保持同级边界：不得把未来事件表或未来事件影响行嵌入下一交易日章节，也不得把未来事件合并进下一交易日影响摘要。可在每日复盘中增加独立的未来窗口预览，并为该窗口单独建立影响摘要；下一美股交易日事件表和影响摘要只能引用下一美股交易日工件中的事件。未来窗口预览仍需沿用五列表头、机械状态和来源/数据状态；其影响摘要仍需使用四列表头，并明确“独立于下一美股交易日”。

复盘完成后的盘中关注点摘要是每日复盘的一部分，不再依赖或启动独立的“盘前交易中心关注点”任务。只有当前 run 的确认门已打开、Wiki 写入成功且回读核验通过后，才在同一份每日复盘中增加该摘要；摘要必须以刚写入的确认版本为基线，只写当日盘中与下一美股交易日的已确认持仓/计划映射、条件或事件窗口、确认/失效边界、风险集中和数据状态，不新增价格判断，不生成买入、卖出、加仓或减仓指令。未来两周或更长窗口的行业/公司事件必须留在独立的未来事件预览及其影响摘要中，不得复制进盘中关注点摘要。该摘要可写入当日 Wiki 日报的脱敏聚合部分；详细券商响应、机械输出、未映射合约和未确认解释仍留在私有运行目录。

### 周度复盘与下周规划

基于 [周度复盘与下周规划模板](assets/weekly-review-and-next-week-plan.md) 组织周六独立周度报告。报告不能退化成周五快照，必须按整周口径覆盖：

1. 账户结果：整周账户净值/总资产的周初、周末、变化额和变化率；如数据可得，同时列每日净值轨迹、外部资金流和净值变化与盈亏的勾稽关系。
2. 交易总览：本周实际成交的标的、买卖方向、订单/成交数量、成交数量汇总和净买入/净卖出；不能用当前持仓或用户口述替代成交事实。
3. 盈亏对比：本周总盈亏金额、盈亏率，以及上一周可比口径；如接口提供，再列盈利/亏损/持平标的数量、已实现/未实现拆分和按标的聚合。接口没有提供的字段写“未提供/未验证”，不自行计算成已确认事实。
4. 计划与过程：周初基线、每日增量、版本变化、计划 vs. 实际、执行纪律和风险暴露。
5. 下周大幅度重规划：明确保留、删除、重写和新增的计划区块，形成待用户确认的下一周基线草案；要把本周账户结果、交易事实和失效条件作为调整依据，但不自动生成买卖指令或直接改写历史版本。
6. 下周重要大事件预览：优先列宏观、央行/利率、财报、监管/地缘和持仓直接相关事件，保留 Asia/Shanghai 与美东时间、状态、来源和数据状态。

整周账户净值、资金流、盈亏、整周订单和整周成交都属于扩展 Longbridge 私有读取范围，必须在本线程明确授权具体读取范围和私有输出路径后才能调用；没有该授权时，仍输出上述栏目，但标记“待用户授权/未验证”，不能用当前持仓快照或上一交易日窗口填充。数值事实优先由确定性脚本/CLI 读取和计算，AI 不负责读取数据或计算关键数字。

### 交易想法、规则与计划同步

一次讨论完成后，直接从 [交易想法卡](assets/trading-idea-card.md) 建立 `待验证` 记录，不使用“研究中”状态。交易想法、触发规则和周度计划保持独立并以链接关联；使用 [周度计划版本记录](assets/weekly-plan-version.md) 固化周初基线和周中修改。

每日复盘先列出当前计划基线、仍在待验证窗口的想法和当天版本变化，再请用户确认新增/修订内容。失效想法直接归档，但必须记录失效证据、规则影响和归档原因；只有发生实际执行、重复失效或风险纪律问题时，才将其升级为周度扩展复盘。

### 项目记录与 Hub 分工

每个定时创建的复盘对话都是一个独立的复盘运行（`run`），不设“主对话”或中心对话门禁。该运行在读取当前 ISO 周基线后，可在**本对话**内完成讨论、确认、创建本周记录或追加本轮版本；权限绑定到已展示的 `run_id`、目标节点和写入包，而非对话的新旧。定时触发本身不构成写入授权。

项目工作树中的 `records/weekly/` 保存每周计划基线和每日增量；Hub 继续负责日常信号与开仓提醒。两者没有可用同步接口时，必须明确写“未同步”，不能把 Hub 的提醒推断成已执行交易。每个 ISO 周建立一个新周度文件，周内只追加 `D1`、`D2` 等增量；用户确认的计划修改递增版本号并记录变更依据，历史版本不删除。独立复盘运行只能创建当前 ISO 周文件，或对已解析出的当前 ISO 周文件追加新版本/纠正增量；不得覆盖历史文本、修改其他 ISO 周，或凭聊天时间猜测目标。需要“当前视图”时由脚本从基线和已确认增量派生，不能用覆盖旧文件的方式制造 latest。

复盘任务在 Wiki 写入并回读成功后，必须由同一独立运行在当前周度文件的每日增量区域追加一条不含券商明细的门禁状态：`run_id=<本轮标识>`、`复盘状态=已完成`、`增量/版本=<本轮标识>`、`Wiki状态=已写入并回读核验`、`完成时间=<Asia/Shanghai>`。同一运行随后以这条状态、返回的 Wiki 节点和在线对应版本/增量为盘中关注摘要的事实基线；只看到用户原始聊天、旧版本或本地“拟写入”草稿，都不能视为完成。

周计划只写研究层和经确认的聚合摘要，不写 Longbridge 原始数量、成本、账户标识或成交明细；Longbridge 当前持仓快照继续留在 Git 工作树外。期权计划只记录标的的位置、触发和失效框架，除非用户另行明确要求，不记录或推断 strike 与到期日。

## 调度设计

- **独立复盘任务**：使用项目级 standalone cron，而不是绑定当前对话的 heartbeat；`Asia/Shanghai` 每周二至周五执行每日复盘，周六 09:00 执行周度复盘，周一和周日不运行。每次运行创建一个新的交易中心对话，读取项目内周度基线和每日增量，不依赖上一次聊天的上下文；该对话可在本轮预览和用户明确确认后自行完成入库，不需要转交主对话。
- **复盘后盘中关注点摘要**：不再设独立的盘前/盘中关注 cron。每日复盘在 Wiki 写入并回读成功后，基于同一确认版本生成并交付盘中关注点摘要；若写入或回读失败，保留失败分类并停止在 Wiki 阶段，不生成该摘要。摘要不读取新的订单/成交、资金、利润或凭据，也不绕过每日复盘的授权边界。
- **固定输出顺序**：每日私有事实包仍按前一美股交易日订单/成交、当前持仓快照、当前周度计划、相关事件视图、计划更新项、Wiki 门禁和最终状态组织；用户可见层只交付对应 HTML 看板。确认门打开且 Wiki 写入/回读成功后，盘中关注点进入同一看板，不另发完整 Markdown。周度按周度报告契约交付。
- **周二至周五**：复盘前一个美股交易日，输出每日计划/想法同步与缺口。成交/订单读取只覆盖该交易日的明确时间窗口，不读取资金、利润、对账单或凭据；周一和周日不运行，周六切换为整周复盘。
- **盘中关注点摘要**：在每日复盘完成后，依据已确认的本周计划、触发/失效规则、Longbridge 当前持仓快照和已核对公开市场数据，列出当天需要关注的条件、事件窗口、风险集中与待确认项；只复述已确认计划，不把计划点位写成已执行结果，也不新增交易指令。
- **周六**：切换为整周周度复盘，比较账户净值、整周交易、盈亏、周度计划基线、想法版本、每日变更与本周事实；随后生成下周大幅度重规划草案和重要大事件预览，并列出下一周第一个美股交易日的盘前关注点候选。
- **讨论后分类写入 Wiki**：自动化先输出本地讨论草稿和待更新差异，并在写入预览中明确分成“本次写入 Wiki / 只保留私有运行目录或当前对话 / 需要逐字段确认”。默认只写用户确认的想法、规则、计划版本、每日/周度复盘结论、相关公开事件摘要，以及取得导入授权后允许的 L1 操作聚合。目标节点、`run_id` 和拟写的“本轮增量写入包”展示后，用户在**该独立复盘对话**说“复盘完成”（或等价的明确确认）即视为确认当前增量内容并授权写入；不要求转交主对话或重复说“写入 Wiki”。原始券商明细始终留在 Git 工作树外。
- **写入后盘中关注**：Wiki 写入和回读核验成功后，必须在同一份每日复盘中输出“Wiki 写入后的盘中关注点摘要”，并将已确认的脱敏摘要追加到当日日报 Wiki。摘要只引用已确认的当前持仓映射、交易计划的触发/确认/失效条件和已核对的公开事件，列出观察条件、时间窗口、数据状态和风险集中提醒；不新增价格判断，不生成买入/卖出指令。周六没有当日美股交易时，输出下一美股交易日的盘中关注点摘要。Wiki 写入失败或用户尚未确认时，停在对应状态，不进入关注摘要阶段。
- **创建/更新前门禁**：先检查已有自动化、时区、重复规则、失败重试与目标项目；展示预览后由用户明确确认。调度任务的 Longbridge 订单/成交授权必须限定为前一美股交易日的只读范围；若授权状态无法在新任务中确认，停止在“待授权”，不调用成交接口。

## 脚本优先与 AI 摘要

优先用确定性脚本完成导出文件读取、字段映射、日期过滤、持仓/账户净值变化计算、整周操作记录排序、去重、盈亏聚合、脱敏和 Markdown 模板填充。脚本输出应包含来源、覆盖范围、缺失字段和可复算的汇总规则；账户净值、资金流、盈亏和整周订单/成交只有在对应授权存在时才能调用。

只有用户确认某类叙述任务可使用 AI 后，才对该任务调用模型。例如：本周过程复盘初稿、重复纪律问题归纳、下周待讨论问题。不得让模型计算关键数值、编造缺失交易事实或替代授权判断。读取任何密钥仅限实际调用前的最小必要范围；不得打印、提交、复制进 Wiki 或保存在 Skill 目录中。模型名、接口地址和密钥文件路径在首次调用前单独确认。

### 本次模型分工与外部 API 边界

本线程已确认采用以下分工：

- 自动化主执行使用 LunaMax，即 Codex 模型 `gpt-5.6-luna`、`reasoning_effort=max`。它负责调度流程、权限与数据状态门禁、规则核验、计划 vs. 实际对照、缺口判断，以及每日看板/周度完整正文的最终交付。
- 事实读取仍由本地确定性脚本和已授权的 Longbridge 只读命令完成；模型不能把自己当作券商数据源，也不能直接读取凭据或扩大 Longbridge 权限。
- DeepSeek API 只用于由本地脚本生成的结构化事实包的读取型摘要、事件摘要、持仓/计划影响摘要和未决项整理。默认适配模型为 `deepseek-v4-flash`，可通过 `DEEPSEEK_MODEL` 覆盖；调用入口是 `scripts/deepseek_summary.py`。不得把原始 Markdown、自由文本备注或未经过字段投影的响应直接交给适配器。
- 发送到 DeepSeek 前必须使用 `trading-center-summary.v1` 脱敏包。不得发送账户标识、订单/成交/交易 ID、凭据、Cookie、API key、原始券商响应、佣金、对账单或私有会话信息。DeepSeek 的返回是摘要层，不是事实源，也不生成买入、卖出、加仓或减仓指令。
- `DEEPSEEK_API_KEY` 未配置、接口报错、返回非 JSON、字段校验失败或输出路径不在私有目录时，必须标记 `DeepSeek摘要=未执行/阻塞`，保留本地确定性事实，不得静默改称“已使用 DeepSeek”或把空摘要当成成功。

适配器只接受私有运行目录中的结构化输入并将结果写回私有运行目录；项目和 Wiki 只保留确认后的脱敏聚合。该分工是模型路由调整，不改变交易只读、Wiki 确认和不下单边界。

### Standalone HTML 复盘看板

每日与周度复盘现在都默认生成私有 HTML 看板。每次每日复盘或周度复盘先读取 [复盘看板可视化契约](references/dashboard-visualization-contract.md)，再运行 `scripts/render_trade_review_dashboard.py`；每日看板不得再因为“未单独要求可视化”而跳过。使用固定资产 `assets/trade-review-dashboard-standalone.html` 直接生成 standalone HTML；不得使用 `document.write`、iframe `srcdoc`、外部 CDN 或运行时脚本拼接。输入 JSON 和成品 HTML 必须位于 Git 工作树外的私有运行目录，模板、脚本和无真实数据的测试才可进入 Git。

每日看板必须与当日私有 Markdown 审计草稿使用同一事实边界和状态：订单、成交、持仓、事件或 DeepSeek 摘要未验证时，看板也必须显示未验证/阻塞，不能用旧快照补齐；Wiki 未写入时不能显示盘中关注点已完成。看板是每日唯一用户可见主交付；渲染成功后只提供私有 HTML 路径和必要状态短说明，不粘贴 Markdown。渲染失败或 Schema 越界时将每日交付标记为 `blocked`，保留私有 Markdown 供诊断，但不得把它当作成功的用户可见替代品。

每日看板固定顺序为：`昨日操作摘要`、`交易计划`、`持仓与计划相关重要事件`。昨日操作摘要使用简洁的 bullet list，不使用摘要卡片；只展示用户确认的操作和本地 LunaMax 判断。授权、账户资产、订单明细和后台系统信息不作为主区块显示，但摘要底部必须保留前一美股交易日、UTC/美东窗口、订单/成交数量与快照净变化的最小事实边界。`交易计划`使用两个 CSS 标签页 `当前持仓` 与 `Plan`：前者只展示当前持仓快照及其已确认的计划语义，后者展示尚未持仓但已进入有效计划的标的；卡片标题不重复添加“当前持仓”或“Plan”前缀。每日看板不显示策略摘要，也不显示本周损益/执行复盘；这些内容按周度契约放入周度正文或周度看板。当前持仓未明确策略时保留“策略未单列”，加仓不另设分类；五类行为标签只归属于已确认的交易计划。默认不采集或展示资金流水；计划卡只能对应明确 ticker，组合暴露、部署状态、证据复核和系统流程不得伪装成独立交易计划；事件区只能使用上述相关事件视图，完整全市场日历继续私存。渲染失败或 Schema 越界时标记 `blocked`，不回退为不稳定的内嵌 HTML。

### 分析 Skill 优先路由

需要市场、宏观、标的、盘面或交易复盘分析时，先读取 [分析 Skill 路由与 Longbridge 能力边界](references/analysis-skill-routing.md)，检查当前 Codex 会话中是否暴露了可用的 `trading-research-system` Skill。优先使用最具体的 Skill：周度计划用 `weekly-trading-plan`，每日盘前和点位滚动用 `daily-market-tracking`，实际成交复盘用 `trade-review`，宏观/行业/公司研究用 `macro-equity-research`，需求不明确时才用 `trading-research` 路由。研究报告、组合风险等任务只有在对应 Skill 当前可调用时才接入。

Longbridge 的 broker skill、Terminal CLI 和 macrodata 是三种不同的数据能力，不能互相替代。先分别做能力状态检查；Skill 不可发现时标记为 `not_installed`，不得假装调用或擅自安装。Skill 只能组织研究和证据，不能扩大本项目授权：Longbridge 默认只读当前持仓；成交、订单、资金、盈亏和账户报表必须在本线程逐次授权；任何 Skill 都不得下单、改撤单或写入券商。

机械事实优先由项目脚本完成，Skill 只负责分析结构、证据分层、多空逻辑、失效条件和下一步核验。所有分析输出注明使用的 Skill、数据能力、时间戳、证据状态和缺口；没有合适 Skill 时，退回到“脚本事实 + 用户口述 + 明确缺口”的受限分析，不自行补充未经验证的投资判断。

### 公开市场事实对齐（不等于账户同步）

当用户要求把口述点位与实际市场走势对齐时，可在不读取任何券商账户数据的前提下运行 `scripts/align_market_watchlist.py`。脚本只调用 Longbridge 的公开标的信息、完成日线、EMA 机械计算、财报/宏观日历和新闻馈送；输出必须放在 Git 工作树外。它将“日线可观察事实”“用户口述解释”和“仍待确认的 ticker/比较基准”分栏，不能用单根 K 线证明多次测试、止损聚集或因果事件。EMA 必须标注历史窗口和机械计算方法，不宣称与交易软件隐藏的完整历史值完全相同。

### Longbridge 周度只读导入（受控）

持仓快照可按已启用的例行只读规则执行；成交、订单、账户净值、利润、资金流、对账单或其他导入仍须同线程明确授权，并提供具体本地导出路径或 CLI 读取范围。每日复盘的默认受限导入仅可调用 `positions`、获授权日期范围内的 `order --history` 与 `order executions --history`；周日只有在本线程明确授权整周账户结果时，才可按指定窗口调用 `assets`、`profit-analysis`、`profit-analysis by-market`、整周 `order --history` 和整周 `order executions --history`；`cash-flow` 只在授权明确包含外部资金流勾稽时调用，`statement` 仍须单独授权。导入前后都遵循 [Longbridge 导入契约](references/longbridge-import-contract.md)：

1. 复述 Longbridge 持仓同步范围或其他新增授权范围、文件路径（如有）、只读性质和输出的私有位置。
2. 检查路径是否在 Git 工作树外；拒绝将原始导出、账户标识、持仓/成交明细或凭据写入项目/Git。
3. 仅读取必要列，声明可用覆盖范围、时间范围和缺失字段；美股订单/成交固定使用 `America/New_York` 日历日对应的 RFC 3339 UTC 半开窗口。查询或解析失败标为“未验证”，只有成功返回空数组才可写“接口在该窗口返回 0 条”。持仓快照可以用于当前计划映射，但不可因单一来源可读就声称历史持仓完整或已对账。
4. 生成“周度复盘草稿”，将导入事实与分析分栏，保留 `数据状态`、`授权状态` 和 `待确认`。
5. 对草稿运行 `python3 scripts/validate_review_draft.py <draft.md>`；验证通过只表示结构和脱敏检查通过，不表示数据完整或结论正确。

例行持仓同步使用 `scripts/sync_longbridge_positions.py`，输出放在 Git 工作树外；该脚本只调用 `positions --format json`，不调用 Longbridge 其他账户接口。持仓同步后的标的别名、基准标的和价格计划仍要与用户口述分开记录，不能把快照解释为计划已执行。

## 写入飞书 Wiki（确认后）

先完成本地草稿和用户审阅。写入预览必须把每一项标为，并明确本轮要追加的增量内容和目标节点：

- **本次写入 Wiki**：确认后的 L0 计划/规则/想法、每日或周度复盘结论、版本与增量、相关公开事件摘要，以及经授权的 L1 操作聚合。
- **只保留私有运行目录或当前对话**：原始券商响应、精确成交/订单明细、当前持仓数量与成本、完整事件/新闻馈送、机械脚本输出、未确认的盘中关注草稿和未映射合约解释。
- **复盘完成后追加的盘中关注摘要**：只写确认版本对应的脱敏观察条件、事件窗口、风险通道、确认/失效边界和数据状态；不写精确持仓、成本、价格级别、订单/成交明细或新的交易指令。
- **逐字段确认后才可写入**：任何 L2 标的数量、价格、成本、订单/成交明细或其他用户未明确要求的字段。

当预览已经展示、且没有未解决的 `run_id`、目标节点或字段范围问题时，用户在当前独立复盘对话明确说“复盘完成”（或等价确认）即视为对当前增量写入包的确认；随后使用已授权的飞书工具写入，并读取回写结果、报告节点、时间和失败项。只追加本轮确认的每日/周度增量，不重写历史版本。不得把券商原始数据、账户标识、成本、价格级别或凭据写入 Wiki，除非用户针对该字段作出明确授权。

Wiki 写入和回读成功后，另在当前周度文件的每日增量区域追加跨任务状态标记：`复盘状态=已完成`、本轮 `D`/版本标识、`Wiki状态=已写入并回读核验` 和 Asia/Shanghai 完成时间。该标记只记录流程状态，不复制券商明细；写入或回读失败时不得写入“已完成”标记。

### Wiki 写入后的盘中关注点摘要（每日复盘交付的一部分）

只有 Wiki 写入成功且回读核验通过，才在同一份每日复盘中进入盘中关注摘要阶段；不再创建独立关注任务。盘中摘要的事件范围严格限定为当天和下一美股交易日；未来两周事件不得进入本节：

1. 以刚写入的确认版本为基线，重新列出当前 Longbridge 持仓与计划的对应关系。
2. 对每个已确认观察对象只写“需观察的条件/事件窗口/失效条件/数据状态”，不把观察条件改写成执行结果。
3. 盘中关注点不得新增计划外标的、价格位或买卖指令；现金约束、风险集中、未映射合约和数据缺口必须单独列出。
4. 若是周六，则输出下一美股交易日的盘中关注点摘要；若 Wiki 写入或回读失败，保留失败分类并停止在 Wiki 阶段，不声称已完成盘中交付。

空间创建与文档创建分开处理：`lark-cli wiki +space-create` 只支持 user 身份；交易中心若没有独立 space，按 [Wiki 文档数据结构](references/feishu-wiki-record-structure.md) 的“无独立 Wiki 时的初始化”小节执行，先检查授权、动态发现、dry-run 和用户确认，不猜 token、不创建替代空间。已有目标 space 且 bot 已加入时，按 `+node-list`、精确标题幂等检查和 `docs +create --as bot --doc-format markdown --parent-token ... --content -` 顺序执行。创建返回中的文档创建状态与 bot 为当前用户授予 `full_access` 的状态必须分开报告。

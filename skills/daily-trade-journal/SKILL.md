# 交易日记助手

把本 Skill 当作一个以对话采访和用户叙述为中心的普通 Obsidian Markdown 记录入口，而不是交易执行器、计划对齐器或账户看板。它维护两组内容：`持仓管理` 和 `计划买入`。按标的记录实际交易工具与具体想法；触发、退出、加仓或减仓条件如果有，就自然写在想法里，不另设必填字段。期权术语使用英文 `Call` / `Put` / `Long Call`。

## 日常工作流

1. 先发现并读取 `25 投资交易` 中的当前计划记录、相关旧日记和当天旧记录，尊重已有手写内容、历史想法和当前落点，不臆造新的真相源。若只有旧不可变计划版本而没有普通计划落点，先向用户确认目标和承接范围，不静默迁移。
2. 再采访用户本次操作、等待原因或计划变化的叙述。已有回答不重复问，只追必要缺口；没有当日叙述时不能自行编出日记，也不能用任务活动替代用户叙述。
3. 把本轮确认的内容整理到 `持仓管理` 或 `计划买入`。每个标的保留实际交易工具和具体想法，清楚区分用户自述、数据事实和分析推断；对未来动作保留“考虑”“可能”等不确定性，不强制固定问卷、评分、机器匹配或后台字段，也不对未完成交易过早下结论。
4. 先展示具体 Markdown 草稿，说明尚未写入。用户说出“确认写入”后，才保存已确认部分；没有变化时返回 `no_op`。

未实施的想法可以继续有效；已买入不代表 `持仓管理` 结束；跨周仍有效的内容沿用，不自动重建、清空或失效。新建或修订仅在展示具体内容并得到用户确认写入后保存，不强制新版本或 schema。

## 技术面与数据核对

只有在用户讨论已筛选标的且请求参考时，才提供轻量 PA 支撑、压力或条件判断。以 Al Brooks Price Action 为主，日线作为背景、小时作为执行；按用户请求读取对应周期数据复验，并注明来源、截至时间、周期和 K 线已完成或形成中。数据、周期或时间不足就报告缺口，不以日线替代小时验证，不把目标价当已证实压力位，也不把触价当成交。用户自行观察的小时内容只能作为自述。

沿用已确定的单一基线券商，未另行指定时默认 Longbridge CLI，按需做行情、持仓和成交的只读核对；不把不同券商持仓/成交混合成同一账户记录。其他券商仅在实际需要时按相同字段含义由 Agent 映射，不预建通用适配层，也不声称现有 helper 已支持多券商。现有 helper 可选且保持不变，它们处理已有输入，不是 Longbridge CLI 封装或多券商接入层。本 Skill 不引入下载器或依赖，不自动调用其他研究 Skill，不重新选股或做基本面，也不把量化研究变成实盘方法。只读能力与本批真实验证分开报告。

数据可用性不构成普通日记的前置条件；券商资料暂缺时仍可如实记录用户想法，但不能把自述标为独立核验的成交、持仓或行情事实。既有不可变版本只作只读历史参考，本轮不原地覆盖或迁移真实记录。

## 周末回顾

周末只回顾本周已经发生的操作和计划实施情况，分别说明已实施、仍等待和缺少证据。仍有效的计划跨周沿用；只有用户明确确认作废，才把具体对象单独展示并归档到现有私有知识库体系。归档不直接删除、不自动失效，归档也需要独立确认。本轮只验证周度行为说明，不创建或修改定时任务；Skill 支持生成周末回顾，调度配置须另获授权，现有自动化未声明同步。

## Obsidian 写入与隐私

继续使用现有目录：

- `25 投资交易/10 每日复盘`
- `25 投资交易/20 周度复盘`
- `25 投资交易/30 已确认计划摘要`

写入前保留可恢复的原版本，重读 live 文件并检查并发变化；未开始写时如有冲突，保留原文并停止。已有 managed 日记只在既有 managed 边界内更新；没有 managed 的普通计划笔记只改用户确认的段落，保留其他手写内容，不强制新建 managed 区域或 schema。写后先做文件系统回读，再按顺序做 Obsidian CLI 回读；回读失败就停止后续写入并报告写入未验证，不宣称成功或自动回滚。需要回滚时先重读，发现新修改不得覆盖。草稿、测试、配置读回和旧自动化状态都不等于真实写入或人类验收。

沿用既有隐私边界：只读取本次核对所需的持仓、成交和行情字段，不下单或修改订单；不扩展到余额、购买力、盈亏或其他不必要的账户信息。账户或请求标识、原始券商响应、凭据、敏感记录和完整期权合约身份不写入仓库、普通日志或公开日记。具体期权合约身份只在已有的、明确授权的私有预览边界内处理，不因本 Skill 扩大授权。不访问或恢复 Web UI、SQLite、Bridge，也不进行真实记录迁移。

## 失败状态

数据缺失、来源过旧、事实无法核验、并发变化或回读失败时保持 `blocked`、`PENDING` 或 `NOT RUN` 等真实状态，并说明缺口；不能把缺数据当成无成交、不能把自述当成核验事实。实施、自动化、测试、外部写入和人类接受分别报告，互不升级状态。

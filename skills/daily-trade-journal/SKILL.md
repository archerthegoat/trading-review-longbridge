# 交易日记编排

本 Skill 是日记编排入口，不是交易执行器、账户看板或 PA 分析器。它维护 `持仓管理`、`计划买入` 和当日日记；PA 工作在用户采访后显式调用 `$al-brooks-pa` 完成。除该独立 Skill 外，不调用其他研究 Skill。

## 日常流程

1. 读取 `25 投资交易` 中当前确认计划、相关旧日记和当天旧记录，保留用户手写内容和历史落点。优先使用当前确认版本；旧 immutable 版本只作只读参考，不静默迁移或覆盖。
2. 复盘前以 Longbridge CLI 只读核对上一完成美股交易日的成交和必要持仓字段。只读核对必须按确认时间、`underlying`、动作和工具对齐；期权的 `Call`/`Put` 方向只作为内部对齐维度，公开投影继续脱敏。优先复用已有 `intraday_revisions` 输入。
3. 先展示脱敏的 broker facts 与对齐结果，再最多问两条必要的交易想法问题。已有回答不重复问；没有用户当日叙述不能自行生成日记。观察是有效的计划状态，但不会让交易自动按计划执行；只有用户明确相反或禁止的证据才标为“偏离计划”。缺失、不完整、未确认或时间无效的证据保持“无法核对”。
4. 用户回复后显式调用 `$al-brooks-pa`，把盘中关注要点带回日记草稿。PA 结果必须区分用户自述、数据事实和分析推断，不能把分析推断写成成交或持仓事实。
5. 展示具体 Markdown 草稿并明确尚未写入。只有用户明确说“确认写入”才保存已确认段落；没有变化返回 `no_op`。

## 日内交易 Set

QQQ 等已筛选标的的日内交易 Set 只是一组“当日有效计划模式”，不建立 UI、数据库或后台执行状态。它在新确认版本中明确形成或修订；当日生成日记时，将 `$al-brooks-pa` 的 `盘中关注要点` 放入草稿。Set、观察清单和计划都不会触发自动下单，也不替代用户的实时决策。

## 状态、工具与失败边界

始终分开报告两条状态：

- broker fact：`complete`、`empty`、`blocked`。`complete` 只表示所需只读响应可解析，不代表计划匹配或账户结论；`empty` 不是“无法核对”的替代，`blocked` 不能降级为无成交。
- journal：`interview_required`、`awaiting_confirmation`、`written`。草稿、测试、配置读回和 CLI 成功都不等于 `written`；未获得确认始终不写入。

仅把确认且时间有效、与标的/动作/工具（必要时含 Call/Put）一致的事实标为“按计划”；明确相反或禁止标为“偏离计划”；其余为“无法核对”。不能把缺失写成无成交、无持仓或已完成 PA。

数据、周期、来源或时间不足时保持 `blocked`/`PENDING`/`NOT RUN`，保留原始失败原因。不要读取余额、购买力、盈亏或凭据，不访问或恢复 Web UI、SQLite、Bridge，不改自动化配置，不把真实 Longbridge、Obsidian 写入或人类验收写成已完成。

## Obsidian 与隐私

确认写入仍使用现有目录：

- `25 投资交易/10 每日复盘`
- `25 投资交易/20 周度复盘`
- `25 投资交易/30 已确认计划摘要`

写入前重读 live 文件并检查并发，保留可恢复原版本；只改用户确认的段落并保留其他手写内容。写后先文件系统回读，再按顺序做 Obsidian CLI 回读；任一回读失败都报告“写入未验证”，不自动回滚或继续写。

公开投影、普通日志和草稿不包含账户/请求标识、原始券商响应、凭据、订单或成交 ID、价格数量费用、余额盈亏或完整期权合约、到期日、行权价和原始代码。已有明确授权的私有核对预览也不因此扩大授权范围。

## 周度回顾

周末只回顾本周已发生操作、仍等待计划和证据缺口；跨周仍有效的计划沿用。作废或归档必须分别展示并取得明确确认，不自动删除、失效或同步。调度、自动化和外部写入不属于本 Skill 的隐含权限。
